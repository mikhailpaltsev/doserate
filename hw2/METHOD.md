## 1. Замысел

- Вопрос: Способен ли программный алгоритм правильно прочитать три повторных измерения для каждой индивидуальной временной точки пациента, восстановить параметры одноэкспоненциальной модели на данных с известным решением и воспроизводимо оценить ошибку прогноза?
- Гипотеза: При соблюдении договора о данных реализация будет выполнять математические ограничения модели и восстанавливать параметры синтетических одноэкспоненциальных кривых в заданных допусках. На синтетических данных с указанным шумом прогноз по экспоненте будет точнее базовой линии.
- Что считается ответом: Вердикт `PASS/FAIL` тестов, таблица ошибок восстановления параметров, RMSE прогноза и парное сравнение с базовой линией с 95%-м доверительным интервалом.

Отдельная научная гипотеза — достаточно ли одной экспоненты для реальных кривых пациентов — в этой домашней работе не считается доказанной: сначала проверяется корректность инструмента для её будущего исследования.

Модель при времени `t ≥ 0`, измеряемом в часах:

\[
D(t) = B + A e^{-\lambda t},\qquad B=0.2\ \text{мкЗв/ч},\ A\geq0,\ \lambda>0\ \text{ч}^{-1}.
\]

Эффективный период полувыведения вычисляется как `ln(2)/λ`. Значение фона `B` в данном эксперименте фиксируется, а не оценивается из данных.

## 2. Постановка

| Что | Значение |
|---|---|
| Что меняем (факторы и уровни) | Вариант прогноза: одноэкспоненциальная подгонка / базовый постоянный прогноз; наличие шума: без шума / аддитивный нормальный шум с `σ = 0.2 мкЗв/ч`; значения `seed`: 11, 22, 33, 44, 55 |
| Что фиксируем | `B = 0.2 мкЗв/ч`, расстояние 3 м, тройные повторы, модель и способ подгонки (нелинейные наименьшие квадраты с `A ≥ 0`, `λ > 0`), синтетические времена `1, 2, 3.5, 24, 48, 72 ч`; в каждом повторе 100 синтетических пациентов |
| Что измеряем, в каких единицах | Ошибки восстановления `A` и `λ` (относительные, безразмерные); RMSE прогноза на 72-м часу (мкЗв/ч); парная разность `RMSE_baseline − RMSE_exp` (мкЗв/ч); количество пройденных тестов |
| Базовая линия | Прогноз на 72-й час = средняя мощность дозы из трёх измерений на 48-м часу (без экстраполяции) |

Обучение на синтетических кривых: индивидуальные параметры подгоняются только по пяти точкам `1, 2, 3.5, 24, 48 ч`; точка `72 ч` используется только для сравнения прогнозов. Обе модели сравниваются на одних и тех же сгенерированных пациентах и seed. Для каждого синтетического пациента независимо генерируются параметры \(A\sim U(5,30)\) мкЗв/ч и \(\lambda\sim U(0.005,0.03)\) ч⁻¹. Каждое из трёх измерений формируется прибавлением независимого нормального шума со стандартным отклонением 0,2 мкЗв/ч к значению модели.

Нормализованная схема CSV: `patient_id, time_h, measurement_1, measurement_2, measurement_3`. Одна строка = одна временная точка одного пациента; время не обязано совпадать между пациентами. Запятая в числах исходного XLSX конвертируется в десятичную точку. Исходные три значения сохраняются; среднее берётся только для подгонки и прогноза.
До проверки глобальной уникальности номеров каждая исходная запись идентифицируется парой (название листа, номер строки Excel). Объединение записей в одну траекторию допускается только после подтверждения, что они относятся к одному пациенту.

Договор о схеме данных — правила, которые проверяет код:

| Правило | Как проверяется | Код нарушения |
|---|---|---|
| Все пять требуемых полей присутствуют и приводятся к ожидаемым типам | Проверка заголовков и преобразования типов в `checks/test_data_contract.py` | `E_SCHEMA` |
| `time_h` — конечное число `≥ 0`, мощность дозы — конечное число `≥ 0` в мкЗв/ч | Числовые проверки и тест на недопустимые значения | `E_VALUE` |
| Ровно три измерения на временную точку | Проверка наличия трёх числовых значений, отсутствия пропусков и корректности разбора XLSX | `E_TRIPLE` |
| Ключ `(patient_id, time_h)` уникален; время может отличаться у разных пациентов | Проверка дубликатов ключа | `E_DUPLICATE` |
| Внутри исходного XLSX число времён равно числу заполненных последовательных ячеек `МАЭД(3) №N` | Проверка парсера и контрольных примеров | `E_LENGTH` |
| Идентификаторы из разных листов не смешивают разных пациентов | Уникальный технический ключ источника `(лист, номер строки)` до подтверждения глобальной уникальности номера пациента | `E_PATIENT_KEY` |
| Временная точка 72 ч не используется для подгонки синтетической модели | Проверка отсутствия пересечения частей «подгонка / проверка» | `E_LEAKAGE` |


Известные нарушения: Исходные листы имеют неодинаковую структуру; предварительный парсер пропускал неполные записи. До численного эксперимента нужно сохранить реестр исключений с причинами. Файл `data_example.txt` — контрольный материал для ручного сравнения, но расхождения с текущим XLSX разбираются отдельно; значения эталона не подменяют значения исходного файла. Наличие 98 записей само по себе не доказывает правильность чтения.

Исходный XLSX, таблица соответствия псевдонимов и любые потенциально идентифицирующие сведения находятся вне публичного Git-репозитория. Для проверяющего используется синтетический пример.

## 5. Верификатор

- Что проверяет: Договор о входных данных; математические свойства функции мощности дозы; восстановление параметров на известных данных; независимость от порядка наблюдений; согласованность единиц и отсутствие смешивания пациентов.
- Команда: `python -m pytest checks -q`
- Где лежит: `checks/` (после создания ограничить запись со стороны агента).
- Чего не проверяет: физическую истинность одноэкспоненциальной модели для всех пациентов, корректность измерительного прибора, систематическую погрешность фона, причины физиологического выведения.

Для тестов на свойствах — список свойств:

| Свойство | Почему должно выполняться | Тест |
|---|---|---|
| 1. `D(t) ≥ B` для `t ≥ 0`, `A ≥ 0`, `λ > 0` | Экспонента положительна; добавочный вклад пациента неотрицателен | `test_model_not_below_background` |
| 2. При `A > 0`, `λ > 0` функция `D(t)` строго убывает | Производная `−Aλexp(−λt) < 0` | `test_model_monotone` |
| 3. На синтетических данных без шума параметры восстанавливаются с относительной ошибкой не более `10⁻³` | Решение известно; это контроль реализации подгонки при идентифицируемых параметрах | `test_recover_noiseless_parameters` |
| 4. Перестановка строк вместе со значениями измерений не меняет результат подгонки сверх `rtol=10⁻⁵` | Порядок наблюдений не входит в функцию потерь | `test_permutation_invariance` |
| 5. Замена часов сутками даёт `λ_day = 24 λ_hour` и ту же `A` с `rtol=10⁻³` | Замена единицы времени не изменяет физическую кривую | `test_time_units_conversion` |
| 6. Перестановка трёх повторов не изменяет их среднее | Среднее арифметическое симметрично | `test_replicate_permutation` |
| 7. Неоднозначные номера пациентов на разных листах не приводят к смешиванию траекторий | Одна кривая должна относиться к одному пациенту | `test_no_patient_mixing` |
| 8. Соответствие времени и измерений | Каждой временной точке должна соответствовать правильная тройка измерений из исходного XLSX | `test_time_measurement_alignment` |

Для конечной точности численных вычислений тесты 4–5 используют относительный допуск; тесты выполняются на заранее выбранных синтетических случаях с параметрами из диапазонов раздела 2. Тесты договора о данных выполняются дополнительно.

Демонстрация силы проверки: преднамеренно внести в отдельной ветке ошибку (например, отсортировать времена без соответствующей перестановки измерений); сохранить красный результат, затем исправить и сохранить зелёный. Исходную рабочую ветку с ошибкой не сдавать как основную.

## 7. Правило принятия (записано до запуска)

1. Метрика и единицы: `RMSE` прогноза мощности дозы на 72-м часу, мкЗв/ч. Дополнительно относительная ошибка оценки `A`, `λ` на данных без шума. Все восемь проверок свойств должны проходить; при проверке параметров без шума ошибка каждой оценки `≤ 10⁻³`. RMSE рассчитывается между прогнозом на 72-м часу и истинным значением синтетической кривой без шума. Обе модели оцениваются относительно одних и тех же истинных значений.
2. Повторы: `r = 5`, seed `11, 22, 33, 44, 55`; по 100 синтетических пациентов в каждом повторе. Одинаковые сгенерированные пациенты и шум для сравниваемых вариантов внутри одного seed.
3. Сравнение: для каждого seed вычислить две RMSE по одинаковым пациентам, затем парную разность `Δ = RMSE_baseline − RMSE_exp`. Для пяти значений `Δ` вычислить среднее, стандартное отклонение и двусторонний 95%-й доверительный интервал среднего по распределению Стьюдента (`df=4`). Преимущество по статистическому критерию фиксировать только при нижней границе интервала `> 0` (эквивалент односторонней проверке на уровне 0,025 для такого интервала). Основное сравнение одно, поправка на множественность не требуется; при добавлении сравнений заранее выбрать и применить поправку Холма.
4. Практический порог улучшения RMSE установлен равным 0,2 мкЗв/ч как заранее выбранный критерий синтетического эксперимента. Он соответствует принятому стандартному отклонению искусственного шума, но не является оценкой погрешности реального оборудования или клинической значимости.
5. Выбор варианта: по среднему пяти парных повторов, не по лучшему seed. Подбор порогов по результатам запрещён.
6. Разбиение для вывода: заключение о прогностическом преимуществе делается исключительно по синтетическим пациентам в отложенной точке 72 ч. Вывод не переносится автоматически на реальные данные пациентов. Временная точка 72 ч недоступна алгоритму подгонки.
7. Остановка: если не выполнены договор о данных, тесты свойств, полные пять повторов или воспроизводимость, зафиксировать `FAIL` и разбирать причину. Если тесты пройдены, но интервал или практический порог не пройдены, результат записать как «алгоритм проверен; преимущество над базовой линией не подтверждено», без подгонки критерия задним числом. После трёх неудачных попыток решения одной подзадачи изменить подход и записать это в журнал.
Итоговый вердикт разделяется: (а) `PASS/FAIL` по корректности реализации и (б) «преимущество подтверждено / не подтверждено» по сравнению с базовой линией. Негативный научный результат не равен сбою верификатора.
